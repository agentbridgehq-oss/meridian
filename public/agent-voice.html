Managed installation — recommended

Meridian handles configuration. You provide approved business facts, account access through secure provider invitations, calendar rules and a human fallback number. Credentials stay in server secret storage.

Technical connection checklist

Railway runs the phone runtime. Configure OPENAI_API_KEY and OPENAI_WEBHOOK_SECRET there. Connect Twilio Elastic SIP to the OpenAI project and route the authorised number to this deployment. Enable calendar and CRM tools only after their signed HTTPS adapters pass verification. Open the full integration guide →

Authenticated customer API

After provisioning, Meridian supplies your actual runtime URL, agent ID and private API key. Send requests from your server. Keep the key out of browser code.

POST /api/v1/agents/:id/health
Authorization: Bearer [your provisioned agent key]

POST /api/v1/agents/:id/chat
Content-Type: application/json
Authorization: Bearer [your provisioned agent key]
{"message":"What services do you provide?"}

This checks the customer API. A real inbound call is a separate phone acceptance test.

Clear limits. Better delivery.

Availability, prices, job status and completed actions come from approved facts and verified tools. When a connection fails, the agent explains the limit and offers an agreed human fallback. The studio never claims a real booking or transfer.
